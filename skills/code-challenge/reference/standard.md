# Review standard

- Favor approval once the change definitely improves the code's overall health. There's no perfect code, only better code.
- A change that worsens it isn't approved, except in an emergency.
- Technical facts and data overrule opinion and preference. The style guide is the authority on style.
- A design choice is judged on engineering principles. Where approaches are equally valid, the author's preference stands.
- With no other rule, match the existing codebase, if that doesn't worsen it.
- A point that only teaches is marked non-blocking.
- An explanation given only in review helps no later reader; ask for it in the code or the doc.
- A disagreement doesn't sit open: settle it by the rules above, then in a conversation whose outcome is recorded, then with a lead or maintainer.
