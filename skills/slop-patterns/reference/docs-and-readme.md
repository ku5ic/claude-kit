# READMEs and docs

A README answers, in order: what is this, should I use it, how do I start, where's the rest. Anything that answers none of those is slop, however polished.

| Tell                                                                                | Instead                                                                |
| ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| A "Features" list of bold label, colon, adjective ("**Fast:** blazing performance") | The three things it does that a reader would search for, each with how |
| A "Why X?" section that sells                                                       | One sentence on the problem it solves, in the first paragraph          |
| Badges that only praise                                                             | Build, version, license; nothing decorative                            |
| Getting Started that installs, then says "and you're ready to go!"                  | Install, one real command, its real output                             |
| Closing "Contributing" and "License" boilerplate copied from a template             | Only what this project's contributors need                             |
| Every section opening with what the section is about to say                         | The content                                                            |
| Paragraphs that summarize the headings above them                                   | Cut                                                                    |
| Importance claims about the project: "a powerful, flexible solution"                | What it is and what it replaces                                        |

Tables over prose for anything with three or more comparable items: `rules/output.md` section 1.
