# Ticket practice

- One ticket is one outcome a person can finish and check.
- It names who gains and what changes for them. Value to the customer counts, not value to just anybody.
- It states the essence, not the details. The how stays with whoever picks it up, unless the source fixes it.
- Small and testable. One that can't be checked, or can't be done in one go, gets cut again.
- Independent. A blocker is a link between tickets, ordered so none waits on a later one.
- No invented estimate. A ticket needs only enough to be ranked and scheduled.
- Acceptance criteria are the checks that make it testable, one per line, each observable. Given, When, Then fits only behavior with that shape, a starting context, an action, and an expected outcome.
- A team's Definition of Done applies to every ticket. Name it once for the batch.
