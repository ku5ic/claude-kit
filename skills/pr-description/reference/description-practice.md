# Description practice

- The title is one imperative sentence naming what the change does, readable alone in a history list: "Delete the X", not "Deleting the X".
- A title like "Fix bug", "Fix build", or "Phase 1" says nothing. Name the bug and the fix.
- The body states the problem, why this approach, and the approach's known shortcomings.
- The PR reads without following a link. A ticket or design doc is background, never the explanation.
- The reasoning is written down, so a later reader can tell whether the decision still holds.
