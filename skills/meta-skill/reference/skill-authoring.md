# Skill authoring

- The description says what the skill does and when it applies, in the third person, key use case first. The listing cuts it at 1,536 characters.
- No `<` or `>` in a description, since they show as entities. Use square brackets.
- The name is lowercase letters, digits, and hyphens, at most 64 characters.
- SKILL.md stays under 500 lines. Reference files link straight from SKILL.md, one level deep.
- A reference file over 100 lines opens with a table of contents.
- After a compaction, a re-attached skill keeps only its first 5,000 tokens. What must hold goes first.
- One term per concept throughout.
- Superseded guidance goes in a collapsed "old patterns" block, never a date-conditional sentence.
