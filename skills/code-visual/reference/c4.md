# C4 views

- Each diagram stands alone, without a narrative: a title with its type and scope in the heading above it, never a Mermaid `title` (the mermaid-patterns skill), and a key for shapes, colors, and line styles. Acronyms are defined.
- Each element names its type (Person, Software System, Container) and has a one-line responsibility.
- Context view: one system in the center, with its people and the external systems it touches. No technology, protocol, or low-level detail; a non-technical reader follows it.
- Container view: one system's containers (an application, or a data store such as a database schema or a file-system folder), plus the people and systems directly connected to them, with each container's responsibility, its main technology, and how containers talk.
- A container view shows no deployment detail: clustering, load balancers, replication, failover.
- One line is one relationship in one direction, labelled with its intent. A single word like "uses" is too vague. A line between containers also names its technology or protocol.
- Color is used consistently, and the view still reads in black and white and to a color-blind reader.
