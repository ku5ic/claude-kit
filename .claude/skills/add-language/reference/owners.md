# Where a language lives in the kit

Each row is one fact about the language, the one place it's kept, and the test that pins it. Read two existing entries in the owner before adding one, and match their shape.

`go/e2e/kit_repo_test.go`, "every language code-graph scans is read by slop and skill_file_map", fails while an extension row 3 adds has no comment syntax (row 4) or doesn't load engineering-fundamentals (row 5). It never checks test-file names, so row 5's `test-patterns` globs are on you.

## What to ask

Ask the researcher, for the language, with a primary source for each:

- Its file extensions, and which tree-sitter grammar ast-grep uses for each (ast-grep's supported-languages page). None: rows 2 and 3 can't be done, so say so.
- Its manifest files, how each declares dependencies, and how a root manifest lists workspace members.
- Its toolchain binaries.
- Every import form, and how an import's name maps to a path on disk (module paths, package directories, source roots).
- Its line comment, block comment, and string quote syntax, and any token that looks like a quote but isn't (Rust's lifetimes).
- Its test file naming, its test-skip and focus forms, its linter-suppression comments, and its assertion forms.
- Its lockfile names.
- Its package registry, and a CLI command that answers whether a package exists, with what it prints for a missing one.
